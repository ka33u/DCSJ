# DCSJ 电磁设计工作台

面向三相异步电动机设计的中文网页工作台，提供版本化 HTTP API 和离线接口文档。支持 macOS、Windows 和 Linux，要求 Python 3.12 或更新版本；CI 使用 Python 3.12 验证。

本仓库只发布应用源码、通用测试和部署说明。**不包含型号库、材料数据、原软件、分析资料及私有计算资源。** 全新克隆可启动界面、API、方案管理；实际电磁计算需要在本机安装授权的私有资源，见 [安装资源说明](data/README.md)。

## 启动

```bash
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell 使用 .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scripts/install_pdf_font.py
python run.py
```

工作台：http://127.0.0.1:8767 ，API 文档：http://127.0.0.1:8767/docs 。首次访问先登录：输入用户名及初始密码 `1234`，自动建立本地账号。也可使用 `start.command` 或 `start.bat`。

启动脚本会核对 `requirements.txt` 中每个依赖的固定版本，缺失或不一致时安装对应版本；再次启动且版本一致时跳过安装。首次安装及升级依赖需要网络。已有 `.venv` 若使用低于 3.12 的 Python，会明确报错并停止；请先安装受支持的 Python，再重命名旧 `.venv` 并重新创建虚拟环境，设计数据无需搬动。

设计、计算记录保存在 `.runtime/projects.sqlite`，与只读型号库分开。通过 `DCSJ_DATA_DIR` 改变运行数据目录，或通过 `DCSJ_PROJECTS_DB` 单独指定设计数据库路径。服务默认只监听本机，适合个人工作站。

## 功能

- 参数编辑、JSON 设计交换、可选的本地型号与材料库。
- 定转子槽型库、图号和适用规格搜索、版本化用户槽型、工作台尺寸带入与气隙校核。
- 私有资源一键导入、校验、版本切换；独立用户型号和材料曲线库，历史版本、同名并存及单位兼容检查。
- 输入校验、电磁计算、性能曲线和明确的计算状态。
- 方案版本历史、并发修改冲突保护、归档与恢复。
- 不可变计算记录；API 支持多方案指标、变化参数及基准差值对比。
- 保存对比与评审说明，重新打开固定结果，输出含全部指标及计算来源的 A4 横向对比报告。
- 快速建模 API：按额定需求寻找本地模板、显式参数修改、转子外径与气隙联动、尺寸预览。

方案对比、自动寻优、A4 打印报告及快速建模均有网页入口，进度及验收门槛见 [ROADMAP.md](ROADMAP.md)。

## API

`GET /api/v1/status` 查看资源与服务状态；`GET /api/v1/schema` 获取字段及单位。
`POST /api/v1/calculate` 接收 `{"parameters": {...}}`，成功后生成独立计算记录。
`POST /api/v1/comparisons` 接收 `calculation_ids` 列表及可选 `baseline_id`。
`POST /api/v1/comparison-sets` 在上述参数中增加 `name` 和可选 `notes`，保存对比；`GET /api/v1/comparison-sets` 分页列出已存记录，`GET /api/v1/comparison-sets/{id}` 返回固定结果。
`GET /api/v1/resources` 查看已安装资源，`POST /api/v1/resources/import` 从私有仓库导入。用户库 API 为 `/api/v1/library/{models|materials}`，文档结构见 `/api/v1/library-schema`；详情见 [资源与用户库说明](data/README.md)。
完整请求、响应和校验规则以 `/docs` 为准。

保存项目允许未完成的草稿；计算时会严格校验。输入 `Ufai` 是绕组相电压。尺寸预览是设计辅助图，不能直接用于加工。

## 0.7.1 接口与计算语义

在 0.7.0 接口改进基础上，0.7.1 取消独立设计要求，恢复原版设计指标流程。默认数值路径保持原版行为。升级会将用户库结构迁移至 v5；历史计算快照不重算、不改写。升级前备份 `.runtime/projects.sqlite`，回退程序时使用升级前备份。

- **恢复原版设计指标**：只编辑 `ATA`、`PF`、`IST`、`TST`、`TM` 一组值，报告与 `requirements` 响应按这组参数比较。`ATA`、`PF`、`IST` 继续沿用原计算初值行为。工作台及输入 schema 已移除独立的 `*_req` 字段；新 API 请求使用这些旧字段会返回 422，并提示对应原字段。打开旧设计、用户型号、快照或导入设计时不再携带独立要求；旧快照及其报告仍保留当时的目标和计算结果。其他 0.7.0 接口改进保留。
- **损耗单位显式化**：`pfw_unit`、`ps_unit` 可填 `W`、`pu`、`legacy`，默认 `legacy`。原规则在单精度转换后以 `>1` 判断 W，否则为额定输出功率比例；显式 `W` 支持 0.8 W、1 W。`loss_semantics` 返回解析单位、核内比例和额定损耗 W。机械损耗在负荷曲线上保持固定 W，杂散损耗按输出功率变化。仅设置正数 `pfw_ref_rpm` 时，启用 `(当前同步转速/参考同步转速)^pfw_speed_exponent` 工程估算，指数默认 2；不自动假设每台机器都适用转速平方律。
- **材料频率**：`material_semantics.loss_curve_frequency_hz=null` 表示原表未声明实测频率；`loss_frequency_model` 单独列出核内 `(f/50)^1.33` 折算及实际因子。这不是实测 60 Hz 材料数据。用户材料继续按现有单位和频率兼容性校验，不能将 60 Hz 实测表直接当作 50 Hz 基表输入。
- **校核与曲线**：`values` 为规范数值输出，`metrics` 是同值元数据视图。`IST1`、`TST1`、`TM1` 用于程序内设计校核与寻优；`curves[].authoritative=false` 表示趋势采样，`curve_checks` 单独返回起动点、采样峰值与校核输出的差值。未拉伸曲线去强制匹配标量输出；该标记不构成实机验证结论。
- **单位契约**：`values_units` 对应原始输出单位；原磁密 G 保留，`values_si` 和 `metrics[].si` 同时给 T。`electrical` 返回接法、相电压和线电压，Y 线电压按 √3 换算，△ 相线电压相同。效率原始数值为比例，图上显示百分比。
- **严格输入**：所有新 HTTP 参数和 overrides 按规范字段名检查。`Kw`、未知字段及历史输出列返回 422，不再静默忽略；请从型号详情的 `inputs` 或 `/example` 取得纯输入。受信任的旧库读入仍兼容 Access 大小写，旧项目未识别原列保留在 `raw_parameters`。备注应放在顶层 `notes`，不要放进 `parameters`。旧导出 JSON 如夹带输出列，需按 schema 的 input 字段清理后再提交。

`GET /api/v1/models` 新增 `frequency_hz`、`poles`、`voltage_v`（相电压）、`power_min`、`power_max`、`frame`（机座数字，如 `180`）、`source_table` 过滤，可与分页及 history 组合。详情 `inputs`/`parameters` 只含输入，`raw_parameters` 和 `historical_results` 分别保留源行和历史结果。

直接从型号试算：

```http
POST /api/v1/models/<model_id>/calculate
Content-Type: application/json

{"overrides":{"f":60,"Ufai":460,"ATA":0.92,"pfw_unit":"W","pfw":200},"persist":false}
```

通用 `/calculate` 同样支持 `persist:false`，默认 true。试算返回 `calculation_id:null`、`persisted:false`，不创建计算记录、审计事件或报告。`base_model_id` 可用于计算和项目保存，来源由服务器查库解析；项目版本和后续对比保留原型号、来源文件摘要和资源包版本。更新项目省略该字段时保留原来源，显式 null 清除来源。来源标识表示派生基础，不表示输入与基础型号完全相同。

`POST /api/v1/calculations/{id}/archive` 接收 `{"archived":true}`，改为 false 恢复；默认列表隐藏归档项，`include_archived=true` 可查看。`DELETE /api/v1/calculations/{id}` 删除未被引用的记录，保存的对比及寻优引用会返回 409。寻优候选继续保留以便核对，可以归档隐藏。

批量清理 `POST /api/v1/calculations/cleanup` 接收 `name_prefix`、带时区的 `after`（含）/`before`（不含），条件组合为 AND，必须至少指定一个。`action` 为 `archive`（默认）或 `delete`；默认 `dry_run:true` 仅预览。返回匹配数量、可处理 ID、跳过原因、是否截断；`limit` 默认 100、最多 1000。确认范围后提交 `dry_run:false` 执行，受引用记录始终不能删除。

PDF 客户端先探测 `/status` 的 `reports.pdf.available`。缺失、损坏或无法读取字体时保持兼容的 503 状态，但返回 `code=PDF_FONT_UNAVAILABLE`、`retryable:false`、`setup` 和 `html_report_url`，并设置 `Content-Location`。安装字体后再请求，不应盲目重试；OpenAPI 已声明相关响应。`embedded` 指生成 PDF 时嵌入字体，**不表示 HTML 内嵌字体**。网页版仍可打印。

## 测试与发布

```bash
python -m pip install -r requirements-dev.txt
python scripts/install_pdf_font.py
python -m pytest -q
npm ci --ignore-scripts --registry=https://registry.npmjs.org
npm test
python tests/smoke_startup.py
python scripts/check_public_scope.py
python scripts/package_release.py
```

公共测试使用人工构造的测试输入，不携带真实型号或材料数据。前端测试需要 Node.js 24.15 以上的 24.x 版本或 26 及以上版本，通过 jsdom 执行实际 HTML 和脚本，检查型号载入、项目版本与归档、快照切换和异步请求顺序；不连接真实服务，也不替代浏览器布局和打印验收。运行应用本身无需 Node.js。私有数值验证仅在安装相应本地资源后运行。CI 覆盖 Windows、macOS 和 Linux；打包脚本只收录通过路径检查的 Git 源码文件。

`smoke_startup.py` 在包含中文和空格的临时源码目录运行对应平台的真实启动脚本：创建新虚拟环境、安装依赖、通过 HTTP 保存及修改人工方案，然后重启并核对版本历史。测试使用独立设计库和已安装的字体，需要安装依赖的网络权限，不读取工作站的设计数据库。

已有数值核仍需实际电机及第三方计算校核，材料损耗单位和最大转矩估计差异有待工程确认。当前版本不宣称完成商用认证或全部设计空间验证。第三方组件见 [THIRD_PARTY.md](THIRD_PARTY.md)。

## 方案、报告和寻优

0.6.4 将工作台、网页打印及 PDF 负荷图的效率纵轴统一显示为 0–100%，功率因数保留 0–1，便于区分两项指标。仅在渲染时同步缩放效率坐标和刻度，曲线形状及拟合方法不变；已保存的合并负荷图也适用，无需重新计算。API 与快照中的原始值及 `plot` 仍保留原来的比值单位，工作台原始数据表明确标注单位。

0.6.3 补齐转子圆端槽（zc=3）、分段槽（zc=4）、双笼槽（zc=5–8）及常见自定义元素槽（zc>20，元素号1/2/4/5）的报告尺寸示意。分段槽按肩角正负区分对称与单侧轮廓；双笼槽保留独立的槽口、连接颈宽与笼间高度。自定义槽沿用原绘图的圆段和首肩高度，若与输入总深不同则同时列出两值，不修改计算输入。负槽口表示的闭口槽、负槽口高度及未确认的特殊分支仍显示对应尺寸/元素表。

0.6.2 将单方案报告首页改为紧凑设计摘要：集中展示额定条件、带尺寸标注的定子与转子槽型、铁心尺寸、绕组导线、设计目标与计算结果、运行与电磁指标。目标取自保存的输入，效率以百分比显示，差值为百分点；最大转矩原公式值与曲线采样峰值分别列出。网页打印和 PDF 均取消“适用边界与计算提示”板块。完整输入、输出和来源仍在后续页。

0.6.1 修正了旧版曲线显示兼容性。M–s 恢复从 1 到 0 的横轴及电流、转矩独立刻度；负荷图恢复 P1、Sn、I1、cosφ、η 五条曲线，以原版文本精度对 9 点作二次最小二乘拟合，显示 20%–150%。30%–120% 外的趋势线是外推。M–s 沿用前 49 点及显示原点，采用有界自然三次样条；原版的边界索引异常未照搬，平滑细节可能有微小差异。

曲线 API 的 `series[].points` 保留原始数值，新增 `plot` 保存显示坐标、独立纵轴、方向、拟合方法及说明。`load_characteristic` 提供合并负荷图；原有三个负荷分图仍返回，标记 `display:false`。网页和报告读取相同显示数据。历史计算快照保持原版本，需重新计算才会生成新曲线。

材料图按原版使用 H1(A/cm) 或 Pfe 作横轴、B1/B2(G) 作纵轴，原始 API 数据仍以 B(T) 及声明的 H 单位返回。材料编辑器提供两张独立采样表、增删行、两种单位格式批量输入及保存前预览；B1 与 B2 不要求同轴或同行数。私有基础材料显示旧版原点，手工材料只连接实际录入点。旧版损耗轴虽标作 W/cm³，物理单位仍待核验，不自动转换为 W/kg。

工作台每次计算都会保存不可变快照。在「方案对比」中选择 2–8 个快照及基准，查看指标差值、变化的输入、计算来源和警告。不同额定工况会明确提示。保存已有设计会创建新版本；其他窗口修改过该设计时返回冲突，可刷新后继续或另存。

运行对比后填写名称与评审说明，点击「保存对比并生成报告」。保存时由服务端读取计算记录，固定方案顺序、基准、指标、单位、差值及来源；后续修改设计或升级不会重算这份对比。缺失指标保留为空，基准为零时不计算变化率。页面底部可重新打开已保存对比，也可通过 `/comparison-reports/{id}` 网页打印或 `/api/v1/comparison-sets/{id}/report.pdf` 直接下载中文 PDF。报告采用 A4 横向，每组重复基准并列出最多三个候选，包含所有对比指标、变化输入、警告和计算来源。完整单方案参数、曲线及尺寸图仍见对应计算报告。

「快速建模」按功率、极数、频率和相电压检索本地模板。修改尺寸或绕组后先校验、预览变化，再载入工作台计算。几何预览展示铁心和槽位，不输出加工图。

选用模板后，可将「气隙输入方式」切换为「由转子外径 D2 联动气隙」。输入转子外径后，按 `g = (Di1 - D2) / 2` 计算径向气隙；修改定子内径时保持 D2 并重新计算气隙。预览列出公式、输入尺寸和修改前后的参数，载入前必须重新校验。切回直接输入后可以独立编辑 g。几何约束为 `0 ≤ Di2 < D2 < Di1 < D1`；联动不推算槽形、绕组、材料或性能。

对应 API 为 `POST /api/v1/modeling/preview`：在 `model_id`、`changes` 外增加可选的数值 `rotor_outer_mm`（mm），例如 `{"model_id":"<模板 ID>","changes":{"Di1":182},"rotor_outer_mm":178.4}` 会得到约 1.8 mm 的气隙。使用联动时 `changes` 不能同时指定 `g`，冲突或无效尺寸返回 422。响应 `linkages` 给出公式、输入值和派生值；省略 `rotor_outer_mm` 时保留原来的直接修改方式。

「自动寻优」从工作台复制一份固定输入，配置 1–6 个几何、绕组或材料变量、目标和性能约束。每个候选均调用真实计算核；额定值、价格、经验修正系数保持固定。任务支持进度、取消、失败诊断、候选复核和基准对比。预算上限为 128 次（包含基准及失败候选），搜索使用可重复的随机种子；结果只代表此次已评估候选中的最佳可行方案，不保证全局最优。

取消在当前一次计算结束后生效。任务和候选存入设计数据库；异常退出后失去心跳的任务会在约 30 秒内标记为中断，保留已有结果，可按原配置重新运行。每个数据库同时执行一个寻优任务，交互计算与寻优共享两个计算席位，最多排队八个任务。

结果页、对比列表与寻优候选提供「网页打印」和「下载 PDF」。单方案的网页及 PDF 报告均从固定快照生成，包含紧凑设计摘要、目标值对照、槽型与尺寸、曲线、完整输入输出及版本指纹。PDF 直接由本机服务生成，嵌入中文字体和矢量图，并处理 A4 分页、重复表头及页码，不依赖浏览器打印设置。

首次运行 `python scripts/install_pdf_font.py` 会从固定版本的 Noto 官方仓库下载字体和许可证、核对 SHA-256，再生成本地常规字重实例。字体缓存默认在 `.runtime/fonts/`，不进入公开仓库。已有字体通过校验后可完全离线重用；PDF 生成过程没有网络请求。`start.command`、`start.bat` 会尝试安装，Docker 构建会预装。也可通过 `DCSJ_PDF_FONT` 指定具有所需字形及嵌入许可的 TrueType 字体。缺少字体时 PDF 接口返回 503，网页打印仍可使用；字体不支持输入字符时返回明确错误，避免静默输出方框。

单方案 PDF API：`GET /api/v1/calculations/{id}/report.pdf`。两类报告共享一个 PDF 生成席位，繁忙时返回 429；下载响应不缓存设计资料。

## 备份与恢复

在线备份使用 SQLite 一致性备份接口，包含已提交的 WAL 数据：

```bash
python scripts/backup.py create .runtime/backups/designs-20261021.sqlite
```

记录命令返回的 SHA-256。恢复到**新的文件路径**，校验后停止服务并通过 `DCSJ_PROJECTS_DB` 切换数据库，再启动服务：

```bash
python scripts/backup.py restore .runtime/restored.sqlite --source .runtime/backups/designs-20261021.sqlite --sha256 <备份摘要>
```

备份和恢复均拒绝覆盖已有文件。设计库包含用户输入及计算结果，应保留在私有存储中。

## 部署

Docker 用户可运行 `docker compose up --build -d`。配置默认只映射 `127.0.0.1:8767`，以非 root 用户运行，并将设计库保存在命名卷中。镜像仅复制源码和空表结构。服务端配置私有资源仓库的只读令牌后，可在「资源与用户数据」中一键导入，无需重建镜像或重启；资源与独立用户库都存入持久卷。离线导入、版本切换、手工材料曲线格式及旧路径兼容见 [资源与用户库说明](data/README.md)。

当前服务是单工作站/可信本地使用模式，不包含多租户权限、计费或商用许可证管理。若部署给多用户，须先在反向代理配置身份认证、TLS 和访问控制；不要直接将无认证 API 暴露到公网。升级前备份设计库，运行测试并保留旧版源码及计算资源；启动会自动迁移旧版设计表，旧版本参数会保留。

程序拒绝打开结构版本高于自身支持版本的设计库，不会将其版本号降级。需要回退应用时，应将升级前备份恢复到新路径再切换；新版本创建的数据仍保留在原数据库中。备份及恢复的 SHA-256 校验采用分块读取，避免大设计库占用等量内存。

## 0.8.0：TX 双层同心式绕组模块

工作台导航中的「双层同心式绕组」打开 `/tx`。TX 使用独立参数和计算资源，提供型号检索、六组匝数与节距编辑、绕组系数与谐波、线圈尺寸、性能与损耗计算，以及可打印的完整报告。无需 Excel 或 Windows 运行环境。

- TX 的几何尺寸采用 **cm**、线径采用 **mm**、功率采用 **kW**、`U1` 采用**线电压**。`D3` 表示定子内径。不能把主模块参数字典直接传给 TX。
- 导入包含 TX 的 v2 私有资源包后可用；旧 v1 资源继续支持主模块。私有资源不在公开源码内。
- 基础型号保持只读，用户通过「保存设计」或「另存副本」创建自己的 TX 设计。修改保存新修订，旧版本可重新载入；同名记录并存。计算保存独立参数、计算资源哈希及结果快照，资源升级和回退不改写既有报告。
- TX 沿用自身材料代码与计算系数。主模块的用户材料曲线尚未接入 TX，不能混用材料参数。
- 计算会拒绝未收敛、溢出及不完整结果；记录可计算不等于经过实机验证。参考性能值保留 TX 原来的输入行为。
- 数据库迁移到 v6，TX 数据与主模块同属 `projects.sqlite` 的不同表，一次备份包含两者。升级前运行 `python scripts/backup.py create /backup/new-name.sqlite`；回退应用需使用升级前备份。

## 0.8.1：目标槽满率与实际线规

修复 [issue #2](https://github.com/ka33u/DCSJ/issues/2)。主模块的 `_wire_target > 0` 会调用原程序的线规反算，此时 `JJ`、`Djj`、`MM`、`Dmm` 输入不参与选线。工作台明确标示此模式并暂时只读这四项；将目标设为 0 后恢复编辑。计算结果列出输入和实际采用规格、目标/实际槽满率及差值。HTML/PDF 报告首页的导线规格使用实际计算值。

`POST /api/v1/calculate` 及型号计算接口新增 `wire_selection`（接口合同 1.2）：

- `mode`：`fixed` 或 `target_fill`。
- `input`：提交的四项线规；`used`：直接从计算后的数值核状态读取的 `JJ / Djj / MM / Dmm`，根数单位为根、直径为 mm。根数为 0 的导线组不参与计算，即使其线径非零。
- `ignored_input_keys`：反算时为上述四个字段；固定线规时为空。
- `target_fill`、`actual_fill`、`fill_delta`：均为 0–1 比例，后者为实际减目标；固定线规时目标及差值为 `null`。`actual_fill` 与 `values.Sf` 相同。反算按原核的可选线规取值，不保证精确命中目标。
- `source`：`kernel-final-state`；完整规格和单位也写入不可变计算快照。

`inputs` 保留提交值，不自动回写，以保持设计版本、输入指纹和历史记录一致。需要固定选中的线规时，将 `wire_selection.used` 四项合入下一次请求的 `parameters`，并设置 `_wire_target: 0`。旧版本的反算记录没有保存实际线规，报告会留空并注明需重新计算，不用旧输入冒充实际规格；旧固定线规记录仍能正常显示。

此次升级不改变原数值核、资源包格式或数据库结构，已安装的 v1/v2 资源包可继续使用，无需重新导入。

## 0.9.0：定转子槽型管理

`/slots` 提供定子、转子分栏查询，可按名称、图号、系列和适用机座搜索，筛选私有参考库或用户槽型。参考资料中未包含的槽宽、槽深、hr0 和面积保持为空；补全尺寸时创建用户副本。用户槽型支持新增、版本历史、另存、归档与恢复，同名记录保留不同 ID。尺寸编辑提供主程序 mm 与 TX cm 两套字段，不自动互换槽型代码。

两个工作台均可选择槽型并预览带入内容，也可把当前槽尺寸存入用户库。适用规格的定子内外径、气隙只有勾选后才带入，槽尺寸之外的绕组、电气和材料参数保持原值。只含图号的记录明确显示“仅图号参考”。计算、设计修订和 JSON 参数文件保留固定版本引用；带入后修改尺寸，输出会标记变化字段。跨机器迁移引用时应同时恢复用户设计数据库和对应私有资源版本；缺失引用会明确报错，可在界面解除关联后独立计算。

报告首页增加图号、槽型版本、本次面积和图纸参考面积。主程序的本次面积是已有受支持尺寸轮廓的单槽几何面积，含槽口、不扣绝缘，圆弧使用绘图三次曲线近似；它不是绕组或导条的有效导体面积。TX 定子单槽面积直接读取原核的 Se 输出。TX 转子及尚无可靠轮廓的特殊槽型显示“未计算”，不会用图纸面积冒充本次结果；图纸面积可单独维护。历史报告只读取保存的快照，不随库更新改变。

气隙校核统一采用 mm 展示，按 `D2 = Di1 − 2g` 计算转子外径（TX 使用 D3、G 并转换 cm）。有成套外径与 hr0 基准时，进一步检查槽颈底直径 `D2 − 2hr0`；仅在同一冲片、该位置不变的前提下，期望值为 `hr0_ref + (D2 − D2_ref) / 2`。该检查不会擅自改写 hr0，偏差容差为 0.001 mm；缺少基准时明确标注未作联动判定。外径输入按钮可由 D2 更新气隙。

新增 API：

- `GET /api/v1/slots`：支持 `q`、`side=stator|rotor`、`module=main|tx`、`source=all|user|resource`、`include_archived`、`limit`、`offset`。
- `GET /api/v1/slots/schema` 与 `GET /api/v1/slots/entry?reference=...`：字段、单位、固定版本详情。
- `POST /api/v1/slots/preview`：`parameters`、`module`、可选 `slot_bindings`，返回面积、匹配状态、几何校核和主程序槽型图。
- `POST /api/v1/slots/capture`：额外提供 `side`，提取当前槽型文档；保存仍走 `/api/v1/library/slots`。
- `POST /api/v1/slots/apply`：额外提供 `reference`、可选 `application`（从 0 起）和 `include_geometry`；返回参数副本、变更清单与 `binding`，不写设计。
- 用户槽型增改、版本、归档复用 `/api/v1/library/slots` 接口，更新需要 `expected_revision`。
- 主设计与 TX 的保存、更新和计算接口新增根级 `slot_bindings`，例如 `{"rotor":"user-slot:<记录ID>@1"}`。更新设计时省略保留已有引用，传 `{}` 清除；计算关联的项目修订与显式槽型引用不一致返回 409。

用户数据库升级到 v8，为主设计修订和 TX 修订增加槽型引用字段。资源格式 v3 可携带私有槽型目录，支持既有 v1/v2 包，资源更新与用户记录保持隔离。发布源码仍不包含私有槽型数据或参考工作簿。

```bash
curl -c /tmp/dcsj-cookies -H 'Content-Type: application/json' -H 'X-DCSJ-Request: 1' \
  -d '{"username":"张工","password":"1234"}' http://127.0.0.1:8767/api/v1/auth/login
curl -b /tmp/dcsj-cookies http://127.0.0.1:8767/api/v1/auth/me
```

## 0.11.0：双目标折中与混合寻优

自动寻优可以同时记录第一目标和可选的第二目标（例如效率与材料成本）。结果显示本次已评估、满足全部约束的非支配方案及散点图，可直接打开任意折中方案继续设计。标记为最佳的方案仍按第一目标选择；图中的集合不代表已求得全局 Pareto 前沿。所有方案保留独立的真实计算快照，重新打开任务不会重新计算或改写结果。

默认仍为原“分层采样 + 局部搜索”，按第一目标推进并汇总第二目标的折中集合。可选“混合差分进化”会用两个目标选择种群，结合基准附近的各变量边界检查、分层采样、差分交叉、局部扰动和可行性优先选择。没有可行方案时按归一化约束超限量引导；目标值不与约束罚分混合。整数、制造步长及材料类别分别处理。小型全离散区域若能在预算内覆盖则完整遍历；其他搜索去重并严格遵守预算，基准及失败计算也计入。额定值、材料单价、损耗经验系数不参与寻优。

API `POST /api/v1/optimization/jobs` 新增 `secondary_objective`（可省略，须与 `objective` 不同）与 `algorithm`（`stratified_v1` 默认，或 `hybrid_de_v1`）。任务详情新增 `pareto_ids`、`feasible_count`；各候选的 `objectives` 和 `violation_score` 来自其已保存的计算快照。旧任务缺少算法字段时重试仍使用原方法。计算期间若数值核、封装或资源包身份改变，任务中断并保留先前结果，避免跨版本混合比较。用户数据库结构不变。

本轮方法参考：异步电机的效率、质量等目标通常存在取舍，可使用非支配排序保留多个方案（[Laouar & Boukadoum, 2024](https://doi.org/10.15598/aeee.v22i3.5327)）；差分进化的群体差分、交叉与整数约束处理参见 [SciPy 官方说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.differential_evolution.html)。本实现使用 Python 标准库，未增加 SciPy 依赖，也未将论文中的改进幅度视作本软件的效果。

验证同时覆盖合成问题和私有型号的固定预算对照。初步对照显示小预算下算法与随机种子会影响结果，混合法尚不能视为原方法的普遍替代，因此保留原默认方法。真实制造可行性仍取决于所设约束及现有模型；热、噪声、公差和整个负载周期尚未纳入自动寻优。`TM1` 仍沿用原程序的最大转矩估计，不能解释为转矩曲线精确峰值。后续迭代将单独验证这些项目。

## 0.12.0：自适应邻域搜索与可复现对照

新增可选方法“自适应邻域搜索”（`algorithm: adaptive_poll_v1`），适合围绕已有方案，在给定范围内逐步试探。每轮固定一个中心，依次尝试各变量方向；有改善时尝试延伸有效方向，无改善时缩小搜索半径，并加入联合扰动和周期性重启。连续尺寸、制造步长、整数绕组数、材料类别分别处理。不可行方案先比较归一化超限量；找到可行方案后优先保留可行结果。双目标时轮流改善两项目标并保留已计算的可行非支配方案，没有新增隐含权重。

原“分层采样 + 局部搜索”继续作为默认方法。独立型号的固定预算对照发现，新方法在部分场景有改善，在其他场景会落后，更多可行方案也不等于最高效率更高。任务详情显示该任务实际使用的方法与随机种子，方便复查历史结果。API 保留现有任务、快照与预算语义；界面方法列表由配置接口提供。用户库结构和电磁计算核心不变。

本轮还修复了候选尺寸统一截断小数可能越过上下限的问题。投影后的尺寸保留实际制造步长，并限制在用户范围内，不再因小数截断把合法边界误判为不可行。

实现参考 [NOMAD 官方文档中的 Search / Poll 与网格细化思路](https://nomad-4-user-guide.readthedocs.io/en/latest/Introduction.html)。这是本程序的邻域搜索策略，不是完整 MADS 或 DMultiMads 实现，也不继承这些算法的收敛保证。文献中的提升幅度不能作为本软件的效果。

新增本地对照工具，无需启动网页服务：

```sh
python -m dcsj.benchmark suite.json --output results.jsonl
```

`suite.json` 包含四个非空数组：`cases`、`algorithms`、`seeds`、`budgets`。每个 case 是 `{"id":"独立用例名","request":{...}}`，其中 `request` 使用寻优 API 的完整参数、变量、目标与约束；算法、种子和预算由其余三个数组逐一组合覆盖。用例参数来自调用者自己的文件，本仓库不提供私有型号数据。

工具在首次计算前校验全部组合，输出文件必须不存在。每行是一个完成的组合，包含输入方案、所有候选的真实结果及可行性、实际评估数、第一目标最佳值、非支配候选序号、配置文件和搜索源码的 SHA-256、数值核及资源包身份。相同输入在同一进程内复用结果，但仍占用每组搜索预算；因此比较求解质量应使用 `evaluated` / `max_evaluations`，不要将受缓存影响的耗时与 `engine_calls` 当作独立性能结论。计算资源发生变化时停止对照，已完成的行保留。完整结果可能含私有设计参数，应保存在用户自己的数据目录。

## 0.13.0：独立的转矩曲线峰值约束

寻优增加 `TM_curve`（转矩曲线采样峰值，单位：额定转矩的倍数）。它与原公式估计 `TM1` 是独立指标，可分别设置，也可同时设置。选择该约束后，服务器自动把任务参数的 `_curve` 设为 `1`，并将实际计算选项写入任务及每个候选快照；工作台草稿不被修改。没有该约束的任务保持原来的曲线开关和判断方式。曲线计算会增加单个候选的耗时，候选预算规则不变。

峰值只取数值核完整返回的 51 个原始计算点：`s=1,0.98,...,0.02,0.01`。末点不是零；绘图用的原点和自然样条均不参与约束。点数、有限值、采样轴、电动状态转矩任一检查失败，峰值返回不可用，该候选不能通过 `TM_curve` 约束；不会退回 TM1 或以零值代替。它不是连续转矩曲线的精确最大值，也不涵盖 `s<0.01` 的未采样区间。

API 示例：在原寻优请求的 `constraints` 中加入 `{"metric":"TM_curve","minimum":3.0}`。配置接口保留原 `constraint_metrics`，另提供 `constraint_labels`，供界面区分采样峰值与原公式值。任务候选增加不可变快照中的 `constraint_values` 和 `torque_peak`，可查看峰值、对应转差率或不可用原因。历史任务缺少这些字段时显示未记录，不补算或改变原判定。

计算结果合同版本为 1.3，增加独立的 `curve_metrics.torque_peak`；原 `values`、设计目标、曲线点及原数值核均不变。任务界面显示实际约束计算值，报告首页可同时列出原公式值、采样峰值及本次峰值约束。用户库结构不变。验证覆盖缺失/不完整/错误采样轴、插值过冲、重复读取历史任务以及原有数值与绘图回归。

研究参考：[TECO-Westinghouse 异步电机参考指南](https://tecowestinghouse.ca/motors/induction-motor-reference-guide-twmi/) 对 breakdown torque 与转矩速度特性的定义。软件保留“采样峰值”的名称，以区分离散模型观察值、原公式估计和实测极限转矩。


## 0.14.0：按负载周期寻优

自动寻优新增“负载周期耗电最低（kWh）”与“负载周期效率最高（比例）”，可与材料成本等目标组合，也可将周期耗电或效率设为约束。选择周期指标后填写每个负载段的输出功率比例和运行小时；界面初始的 50% × 4 小时、75% × 2 小时、100% × 2 小时只是可编辑示例。时长属于本次配置的周期，不自动换算成年耗电。

计算采用完整的 9 个原始负载采样，范围为额定输出功率的 30%–120%。落在采样点时直接取未舍入的输入功率，点间仅对输入功率做线性插值，不使用二次绘图趋势或外推。周期耗电为 `Σ(P1_kW × hours)`，周期效率为 `Σ(P2_kW × hours) / Σ(P1_kW × hours)`，不是各点效率的平均值。额定功率和负载周期固定时，这两项目标等价，因此不能同时作为两个独立目标。

评估会检查采样数量、坐标、有限值、电动状态及输入功率与效率的能量关系；无效采样不会得到周期目标值，不借用额定效率替代。该计算表示固定电压、频率下稳态负载段的能耗估计，不计算启停过渡、变频器损耗或热积累；120% 是数据覆盖范围，不是连续过载能力承诺。研究依据：[美国能源部《Determining Electric Motor Load and Efficiency》](https://www.energy.gov/sites/default/files/2014/04/f15/10097517.pdf) 建议结合负载和运行时间评估电机用能。采样范围和插值方法来自本程序的数值数据边界，不是该资料规定的方法。

API 的寻优请求新增可选 `load_cycle`，例如 `[{"load_fraction":0.5,"hours":4},{"load_fraction":0.75,"hours":2},{"load_fraction":1,"hours":2}]`，最多 32 段，每段小时数大于 0、至多 1,000,000。选择 `cycle_energy` / `cycle_efficiency` 目标或约束时必须提供该字段；提供周期会自动将任务副本的 `_load_curve` 设为 1，不改变工作台草稿。旧请求和旧快照保持原有行为。

候选快照的 `optimization.load_cycle` 保存周期配置、原始功率采样、各段插值权重、输入/输出功率、电量、效率、算法标识和源码校验值。任务详情、打开候选及 HTML/PDF 报告均读取保存的结果，历史记录不会重算。基准对比显示同一周期的耗电差。基准测试工具只缓存数值核结果，不复用其他负载周期的累计能耗。

## 0.15.0：指定规格与气隙联动

搜索变量新增“指定规格”，适合从已确认可用的线径、导体数、并绕根数、并联支路或铁心长度中选值。每个数值变量最多 64 个不同规格，可与范围/步长变量、材料候选混合使用；三种搜索方法均遵守清单。小型全离散区域能在预算内覆盖时完整遍历。基准始终按原参数计算，不在清单中的基准只供比较，不能成为最佳方案。原型号库中标称值的精确单精度表示（如 0.8 对应 0.800000011920929）视为同一规格并去重，不用宽松误差吸收其他尺寸。

API 示例：`variables` 中使用 `{"key":"Djj","values":[0.71,0.8,0.9]}` 或 `{"key":"a","values":[1,2,4]}`。`values` 不能与 `minimum`、`maximum`、`step`、`choices` 同时提供；材料继续使用 `choices`。这些数字仅演示接口格式，不代表任意电机都能采用这些支路或线规。线径为裸线直径，不能填入含漆膜外径。绕组连接允许的支路和实际供应规格由用户确认，当前模块不生成完整绕组接线图。

气隙参与搜索时，可选“保持槽颈底位置，联动 hr0”。请求字段为 `rotor_gap_mode: "fixed_neck_bottom"`；保持定子内径和槽身参数，用 `D2 = Di1 − 2g`、`hr0 = hr0基准 + g基准 − g` 保持 `D2 − 2hr0` 不变。服务器预先拒绝使 hr0 为负或槽颈底落入轴孔的配置。默认 `independent` 保留原 hr0 输入值，历史请求无需修改。

候选快照 `optimization.manufacturing` 记录允许规格、实际输入、标称匹配，以及联动前后的气隙、转子外径、hr0 和槽颈底直径。任务、候选结果及 HTML/PDF 报告读取这些固定记录，旧快照不补算。此功能验证指定条件；温升、噪声和制造公差仍未作为鲁棒约束。

研究依据：[Altair FluxMotor 绕组说明](https://help.altair.com/FluxMotor/topics/3605-Automaticmode.htm) 将可用并联支路与绕组连接关联；[Elektrisola 技术表](https://www.elektrisola.com/Attachments/TechnicalDataBySize/ELEKTRISOLA_EnCuWire_IECJIS_Datasheet_eng.pdf) 区分裸线标称直径、公差和不同漆膜等级的外径。规格清单和几何联动为本系统实现，不声称通过这些资料认证。


## 0.16.0：制造公差情景寻优

自动寻优可选“按公差情景寻优”：输入 1–3 个尺寸的对称允许偏差（`L`、`g`、`Djj`、`Dmm`，单位 mm），每个名义方案计算中心点和全部角点，共 3 / 5 / 9 次。所有采样均满足约束，候选才可行；最大化目标取采样最小值，最小化目标取采样最大值。双目标分别取最不利值，可能来自不同情景。三种搜索算法均可使用。

气隙偏差可保持名义 `hr0`，或在槽颈底位置固定时按 `hr0样本 = hr0名义 − Δg` 联动。这个选择独立于名义搜索的尺寸联动。规格清单和搜索范围约束名义值；公差样本不会被吸附回规格清单。公差由使用者确认，界面不预设工厂允许偏差。无效尺寸或计算失败均计入预算且使该组不可行。

`POST /api/v1/optimization/jobs` 新增可选字段：

```json
{
  "tolerances": [{"key": "g", "delta": 0.01}, {"key": "L", "delta": 1}],
  "tolerance_gap_mode": "fixed_neck_bottom",
  "max_evaluations": 30
}
```

以上仅为字段示例，需配合完整参数、搜索变量与约束；偏差不是推荐生产值。预算按**情景计算次数**计，包含基准、无效和失败情景；至少容纳基准和一个候选的完整评估。上述两项公差每组需 5 次，预算 30 最多评估 6 个名义方案。剩余预算不足完整一组时停止。省略 `tolerances` 保持普通寻优行为。

每次采样即时保存，任务 `samples` 返回输入、指标、约束诊断、错误与原始快照 ID；完整候选另有汇总快照。汇总快照的常规指标、曲线、负载周期是名义值，`optimization.robustness` 保存最不利目标、情景编号及采样范围；未完成或失败组的目标值为空。网页与 PDF 单列公差评估，历史任务与报告只读已保存的结果。取消或进程中断保留已完成样本；重试创建新任务。用户库结构升至 v11，增加采样与汇总表，保留旧设计、账号和计算记录。

本功能是有限中心/角点校核，不推定公差分布、失效概率或合格率，不保证角点之间没有更差结果；均匀气隙变化也不代表偏心。研究依据：[Li 等，考虑制造公差的异步机损耗优化（2022）](https://link.springer.com/article/10.1007/s00158-022-03276-z)，其公开摘要讨论制造偏差对损耗与启动性能的影响，采用有限元代理与概率可靠性方法。本系统使用现有数值核逐点计算，未复现该论文方法，也不套用其性能收益。

## 0.17.0：加密转矩峰值约束

自动寻优的约束列表新增 `TM_refined · 加密转矩峰值（收紧迭代，倍）`。选择后自动启用转差率曲线，保留 `TM1` 原公式值和 `TM_curve` 原始 51 点峰值，并另外计算收紧迭代后的采样峰值。未选择时不增加这项计算。普通寻优、公差情景寻优均支持；公差模式要求每个情景的加密峰值满足约束。HTTP API 在 `POST /api/v1/optimization/jobs` 的 `constraints` 中使用 `{"metric":"TM_refined","minimum":3.3}`，其余请求结构不变。

原扫描将上一个转差率点的迭代状态传给下一点，电流倍数差小于约 0.01 时结束。新方法从原扫描首点的独立状态副本出发，在原 51 个转差率上重新求解，将这一个比较条件收紧至 0.00001；电磁运算仍执行原 SATU、SKIN 和 SM 指令。随后在每个已观测局部峰值两侧进行有界网格加密，最多 257 个直接计算点。计算只覆盖 s=0.01–1；有限采样不保证连续全局峰值，收敛残差也不是转矩误差界或实测精度。该能力限定于已验证的数值核哈希，核不匹配、原曲线不完整、迭代失败或预算耗尽时返回无有效值，候选不满足此约束。

快照的 `curve_metrics.refined_torque_peak` 保存方法、采样范围、容差、全部直接计算点、迭代次数、末次电流倍数差和指令数。寻优列表、结果页、HTML 与 PDF 报告显示独立的加密峰值校核；重开历史结果读取已保存记录，不重新计算。无需数据库迁移或重建私有资源包。

方法依据：[异步机转矩与电流特性研究摘要](https://iris.polito.it/handle/11583/2701397)强调饱和、集肤效应和温度模型对预测的影响；[SciPy 一维优化文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.minimize_scalar.html)说明局部优化的范围。这些资料用于确定数值校核方向，并不验证本程序的工程精度。

## 0.17.1：未收敛采样诊断

加密峰值采样失败时，`curve_metrics.refined_torque_peak.diagnostic` 保存失败类别、末次残差、迭代次数、实际指令数和最多 12 条末段迭代记录。记录包含输入/输出电流倍数、饱和插值输入、系数与分段编号；只有同一组状态连续精确重复至少三个周期，才标注周期 1–4 的重复。周期诊断在原迭代上限退出后进行，不提前中断，也不更改原插值或收敛条件。对于带有诊断的失败采样，`steps` 同时计入其实际执行的指令，避免低估工作量。

结果页、HTML 与 PDF 可查看已保存的迭代明细。公差情景中，必需的加密峰值无法求得时按数值校核失败记录，汇总目标为空；有完整数值但未达到约束的情景仍显示其有效目标值。数值求解失败本身不能证明电机性能不达标。既有快照读取原记录，无需数据库迁移或资源包更新。

研究参考：[饱和异步机磁等效电路的非线性求解方法比较（2024，公开摘要）](https://journals.sagepub.com/doi/abs/10.3233/JAE-230237)与 [PETSc 的阻尼固定点迭代文档](https://petsc.org/release/manualpages/SNES/SNESNRICHARDSON/)。原核饱和表局部三点二次插值在更换取点范围时可能不连续；本轮诊断保留这种原始行为。连续插值及混合求解属于进一步模型验证工作，尚未替代生产计算。


## 0.18.0：连续饱和插值转矩约束（试验）

自动寻优新增可选约束 `TM_continuous · 转矩峰值（连续饱和插值，试验，倍）`，适用于研究原饱和系数查表换段引起的转矩迭代振荡。API 在 `POST /api/v1/optimization/jobs` 的 `constraints` 中使用 `{"metric":"TM_continuous","minimum":3.3}`。它可与 `TM_refined` 同时选择；两种模型独立求解、分别满足约束，缓存也分开保存。未选择时不执行试验模型。

该选项仅改变独立转矩采样中 SATU 的饱和系数插值，使用运行时原表节点与低饱和解析段端点构建保形三次插值（PCHIP），不对表外数值外推。表内插值连续且保持单调，和低饱和解析段的连接保证函数值连续，不承诺该连接点的导数连续。每点仍运行原 SM/SKIN 运算，电流倍数差及第二迭代状态差均须小于 `1e-5`；任一点未收敛、超出表域或超出采样预算，整项峰值不可用，不回退到其他峰值。公差寻优要求每个情景都完成数值校核。

**这是改变插值规则的试验模型，并非原软件复算精度或物理预测精度的提升。** 常规效率、功率因数、损耗、`TM1` 与原曲线保留原模型，连续模型仅用于这项转矩约束；仍需独立工程校核。有限采样也不保证连续全局峰值。快照的 `curve_metrics.continuous_torque_peak` 保存方法标识、模型作用范围、全部采样点及两种状态差；工作台与 HTML/PDF 报告分别展示原加密峰值和试验峰值，重开历史记录不重新计算。

方法参考：[SciPy PCHIP 官方说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.PchipInterpolator.html)中的保形斜率构造；对固定点迭代阻尼的研究参考 [PETSc Richardson 非线性求解说明](https://petsc.org/release/manualpages/SNES/SNESNRICHARDSON/)。运行程序不需要 SciPy；独立对照、原型号试算与数值诊断均留在私有验证目录。


## 0.18.1：连续插值模式的双状态收敛

修正试验转矩模型在低转差率处可能过早结束迭代的问题：此前原 SM 循环仅由电流差控制，退出后再检查第二状态；当电流先收敛、第二状态尚未收敛时，该采样会被拒绝。现在用两个状态更新量绝对值的最大值控制停止，保持 `1e-5` 阈值及原有迭代次数、指令预算限制，不通过放宽阈值接受结果。数值方法标识更新为 `independent-sm-pchip-saturation-v2`，快照保存 `convergence_rule`；若仍未完成求解，诊断同时记录末次电流差与第二状态差。

原 `TM_refined` 的停止规则与常规计算不变，历史快照保持原方法记录。该修改只改善试验模型的数值求解，不提供物理精度保证。停止准则的研究参考 [PETSc 对迭代状态、步长及残差范数的说明](https://petsc.org/release/manualpages/SNES/SNESConvergedDefault/)；这里采用固定点映射两个更新量的最大范数，没有引入 PETSc 运行依赖。
